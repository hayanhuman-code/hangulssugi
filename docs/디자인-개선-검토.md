## 한 줄 결론

**색·바탕**과 **획 가이드의 대비 위계** 두 가지가 아직 v1 에 머물러 있고, 이 둘이 화면 인상의 대부분을
결정한다. 나머지(잠금 톤, 3층 가이드, 터치 타깃, 접근성)는 시안을 상당 부분 따라왔다.
아래는 고치는 순서대로 적었다.

---

## P0 — 먼저 고칠 것

### 1. 배경이 아직 v1 의 무지개 파스텔이다

`index.html:21` 의 `body` 와 `index.html:28-34` 의 `.home` 이 분홍·하늘·노랑·연두 4색 방사
그라데이션을 겹쳐 쓴다. 시안은 앱 배경을 **`#FFF8EE` 단색 크림** 하나로 못 박았고, 레퍼런스 앱도
전 화면이 같은 크림(≈`#FDF4DE`) 단색이다.

지금 화면에서 실제로 벌어지는 일:

- 흰 카드(`#FFFFFF`)와 배경의 경계가 위치에 따라 사라진다. 홈 캡처에서 오른쪽 위 카드들은 테두리가
  보이지 않는다.
- 배경색이 화면마다 달라서, 같은 흰 카드가 왼쪽에서는 분홍빛, 오른쪽에서는 푸른빛으로 읽힌다.
- 그림자가 `rgba(0,0,0,…)` 인데 시안은 `rgba(90,74,56,…)` 이다. 따뜻한 바탕 위의 회색 그림자는
  때가 탄 것처럼 보인다.

→ 배경 `#FFF8EE`, 가라앉은 면 `#F6EEE1`, 그림자 `0 6px 0 rgba(90,74,56,.12), 0 12px 24px
rgba(90,74,56,.08)` 로 교체. 홈 제목의 무지개 그라데이션 텍스트(`index.html:42`)도 같이 정리한다 —
시안의 제목은 `#3B3226` 단색 34px "오늘은 뭐 써 볼까?" 다.

### 2. 캔버스가 푸른 종이에 점선 액자를 두르고 있다

`index.html:309-311`: 캔버스 배경이 `#FAFAFF → #F0F4FF` 푸른 그라데이션이고, 그 위에
`4px dashed #D4D4E5` 테두리가 둘러져 있다.

- 시안의 캔버스는 **`#FFFDF8` 크림 단색, r40, 테두리 없음**. 획 색의 4.5:1 기준은 이 배경을 전제로
  계산된 값이라, 배경이 바뀌면 기준 자체가 무너진다(아래 대비표).
- 점선 테두리가 문제다. 바로 안쪽에서 **가이드 점선**이 같은 "점선"이라는 언어를 쓰고 있어서 둘이
  경쟁한다. 레퍼런스 앱에는 액자가 아예 없다 — 화면 전체가 종이다.

→ 테두리 제거, 배경 `#FFFDF8`.

### 3. 시작 번호와 화살표가 획을 덮는다

시안이 명시한 규칙: *"화살표·번호는 띠 안쪽이 아니라 획의 **시작점과 끝점 바깥**에 배치"*.
레퍼런스 ②가 정확히 그렇게 한다 — 시작점 **위**에 노란 원 + 아래 방향 화살표, 끝점에 큰 화살촉 하나.

현재(`app.js:778-798`, `app.js:800-820`):

- 번호 배지가 시작점 **위에 그대로 얹혀** 획의 시작 캡을 가린다. 캡처를 보면 ㄱ 의 왼쪽 끝이 "1" 원에
  먹혀 있다.
- 화살촉이 띠 **중간에 2~3개** 흩어져 있고, 흰 테두리 때문에 점선을 갉아먹은 자국처럼 보인다.
  "이 방향" 이 아니라 "여기 뭔가 지저분함" 으로 읽힌다.

→ 배지는 시작점에서 획 방향 반대쪽으로 오프셋해 띠 **바깥**에, 화살촉은 **끝점 바깥에 하나만**.
중간 화살표는 없앤다.

### 4. 잠긴 카드가 화면의 대부분이다

`app.js:94` 의 `HEAD_START = 3`. 첫 실행 화면에서 숫자는 21개 중 18개, 단어는 36개 중 33개가 회색
카드다. 잠금 **톤**은 시안대로(경고색 없음, 평평, 통통 튀는 반응) 잘 되어 있는데, **비율**이 문제다.
아이가 앱을 처음 열었을 때 보는 것이 "거의 다 막혀 있는 판" 이다.

→ 셋 중 하나를 고른다.
- `HEAD_START` 를 6~8로 올린다(가장 싸다).
- 잠긴 항목을 그리드에서 빼고 아래에 "다음에 만나요" 구역으로 접는다.
- 카테고리 단위로만 잠그고 카테고리 안에서는 자유롭게 고르게 한다.

### 5. 완료가 모달로 화면을 덮는다

`showCelebration()` 이 배경을 흐리는 전면 오버레이를 띄우고, 카드 안에 **버튼 두 개**("좋아요" /
"혼자 써볼래요!")를 놓는다. 캡처에서 아이가 방금 그린 선은 블러 뒤로 사라진다.

레퍼런스 ③은 **도장**이다. 종이 위에 "참 잘했어요" 도장이 찍히고, 아이가 쓴 글자는 그대로 남는다.
만 4세에게 선택지 2개짜리 모달은 그 자체가 과제이고, 자기 결과물을 못 보게 가리는 건 보상의 반대다.

→ 별·컨페티는 살리되 화면을 덮지 않는 형태(캔버스 위 도장 + 1.2초 뒤 자동 진행)로 바꾼다.
시안도 *"단계 전환은 자동. 되돌아가기 버튼 없음"* 이라고 적었다.

## P1 — 그다음

### 6. 버튼이 시안보다 작고, 1단계만 자리가 다르다

| | 시안 | 현재 |
|---|---|---|
| 주요 CTA | h88 · r28 · 텍스트 32 | `min-height:60` · 텍스트 22 (`index.html:402`) |
| 아이콘 버튼 | 112 × 112 · 아이콘 46 + 라벨 18 | 72 × 60 · 아이콘 25 + 라벨 14 (`index.html:397-400`) |
| 소리 듣기 | 132 원형, 전 화면 좌측 하단 고정 | 다른 버튼과 같은 크기로 액션바 안 |

만 4세 손가락 기준으로 72×60은 작다. 그리고 시안이 따로 적어 둔 규칙 — *"세 단계 모두 버튼 자리는
왼쪽부터 같은 순서로 고정, 다시보기는 항상 첫 칸"* — 이 지켜지지 않는다. 1단계는 액션바에 다시보기가
없고 캔버스 위에 떠 있어서(`.canvas-wrapper.with-replay` 가 캔버스 아래 68px 을 비우는 보정까지
필요하다), 2단계로 넘어가면 버튼이 통째로 자리를 옮긴 것처럼 보인다.

→ 다시보기를 1단계에서도 액션바 첫 칸에 두면 `with-replay` 보정도 같이 사라진다.

### 7. 진행 중 단계 칩이 CTA 와 같은 색이다

`index.html:208` 의 `.step-dot.active` 가 `linear-gradient(135deg, #FFA94D, #FF6B9D)` 인데,
`.btn-primary` 도 같은 계열의 주황→분홍 그라데이션이다. 화면에서 가장 눈에 띄는 두 요소가 같은 옷을
입고 있으니 칩이 눌리는 것으로 오독된다.

→ 시안대로 진행 중 `#3F9E6C` 면 + 흰 글자, 완료 `#8FD8B0` 면 + 체크. 그라데이션은 CTA 한 곳에만.
덤으로 대기 칩 라벨 `#b8b8d0` 은 흰 배경 위 **1.94:1** 이라 캡처에서 "3 혼자쓰기" 가 거의 안 보인다.

### 8. 좌측 정보 패널이 넓고 비었다

`index.html:227` 의 `1fr 1.4fr` 은 1180 폭에서 **463 / 649** 로 나뉜다. 시안은 **332 / 748** 이다.
좌 패널이 130px 넓고 캔버스가 100px 좁다. 게다가 패널이 큰 흰 카드 한 장이고 내용이 세로 가운데에
뭉쳐 있어서, 캡처에서 위아래로 각각 화면 높이의 20% 가까이가 빈 흰 면이다.

→ 시안대로 폭을 332로 줄이고, 한 장의 큰 카드 대신 **내용에 맞춰 붙는 카드 2장**(글자+이름 / 대표
단어)으로 나눈 뒤 남는 공간은 그냥 비운다. 소리 듣기 원형 버튼은 `margin-top:auto` 로 좌측 하단 고정.

### 9. 3단계 가이드가 2단계 띠와 같은 모양이다

`renderStepSolo()`(`app.js:821`)는 굵기 `sw * 0.8`, `opacity .15` 의 **꽉 찬 띠**를 그린다. 2단계의
띠(`opacity .15`)와 모양이 같아서, "혼자 쓰기" 인데 여전히 따라 그릴 면이 놓여 있는 셈이다.

→ 시안: *"외곽선 = 딥색 28% 굵기 44 위에 캔버스색 38 → 실선 두께 3"*. 면이 아니라 **윤곽선**이어야
2단계와 다른 과제로 읽힌다.

### 10. 아이가 그은 선이 가이드보다 얇다

`app.js:898` 의 `ctx.lineWidth = 18` 인데 가이드 띠는 30이다. 아이 선이 띠 안에서 헐렁하게 놀아서
"칸을 채웠다" 는 만족이 나오지 않는다. 시안은 아이 선 굵기 **40**, 띠 44 로 거의 꽉 차게 잡았다.

## P2 — 결정이 필요한 것

### 11. 숫자만 21가지 색이다

`number-data.js` 는 숫자마다 다른 강조색을 쓰는데(v1 유산), 시안은 **카테고리당 딥색 하나**다
(숫자 `#2F6BD8`). 한글 4개 카테고리는 이미 시안 팔레트를 따르고 있어서(`hangul-data.js:230-233`)
숫자 탭만 규칙이 다르다. 아래 대비표대로 숫자 색들은 4.5:1 을 크게 밑돌기도 한다.

→ 카드 배경 파스텔은 숫자별로 두더라도 **획 색은 카테고리 딥색 하나**로 통일하는 쪽을 권한다.

### 12. 그리드가 세로 스크롤이다

시안: *"글자·단어가 15개를 넘으면 세로 스크롤 대신 **가로 페이지 넘김 + 하단 점 인디케이터**"*.
현재는 `.number-grid.scrolly` 로 세로 스크롤인데 스크롤 힌트가 없어서, 단어 탭의 "단어 넣기" 카드는
화면 밖에 있고 존재를 알 수 없다. 만 4세는 세로 스크롤을 잘 하지 못한다.

### 13. 이모지를 아이콘으로 쓰고 있다

🎬 🧽 🔊 👀 ✏️ 🌟 는 OS 마다 그림이 달라지고, 애플의 3D 이모지는 시안·레퍼런스의 납작한 일러스트
톤과 어긋난다. 레퍼런스 앱은 전부 커스텀 아이콘이다.

→ 최소한 다시보기 / 지우기 / 소리 세 개는 단색 SVG 아이콘으로 교체.

### 14. 위계가 크기로만 존재한다

지금은 `Gothic A1 700` 하나로 제목·본문·글자를 다 쓴다. 시안의 스케일(96 / 44 / 34 / 30 / 24 / 18)을
그대로 가져오면 굵기를 안 바꿔도 위계가 선다. (글꼴을 Jua 대신 고딕으로 간다는 결정은 `docs/README.md`
대로 유지 — 스케일만 빌려 온다.)

## 레퍼런스 앱에서 가져올 것

- **필기구 트레이**(②) — 연필 3색 + 지우개가 종이 아래 놓여 있다. 색을 고르는 행위 자체가 아이에게
  소유감을 준다. 지금은 획 색이 카테고리색으로 고정이다.
- **도장 완료**(③) — 위 5번.
- **아이 화면의 컨트롤은 두 개**(①②③) — 닫기와 소리뿐이다. 우리 연습 화면 상단에는 뒤로 + 단계 칩
  3개가 있는데, 칩은 누를 수 없는 표시이므로 더 조용해도 된다.
- **시작 배지 안의 방향 아이콘**(②) — 숫자 대신(또는 함께) 아래 화살표가 들어 있어서, 숫자를 못 읽는
  아이도 첫 획의 방향을 안다.

## 레퍼런스 앱에서 따라 하지 말 것

- ① 마스코트 손이 획의 절반을 가린다. 시범을 보이는 그 글자를 가리는 건 시범이 아니다.
- ③ 완료 도장이 글자와 겹쳐 아이가 방금 쓴 결과를 덮는다. 도장은 여백에 찍혀야 한다.
- ② 필통이 화면 아래로 잘려 있다. 세이프 영역을 벗어난 장식이다.

## 부록 B — 대비 측정치

캔버스 배경 대비 획 색(WCAG 대비비). 시안이 요구하는 값은 **4.5:1** 이다.

| 획 색 | 현재 캔버스 하단 `#F0F4FF` | 시안 캔버스 `#FFFDF8` |
|---|---|---|
| 자음 `#C9512A` | 4.07 | 4.40 |
| 모음 `#0E7D66` | 4.61 | 4.98 |
| 글자 `#7B4FC0` | 5.13 | 5.55 |
| 단어 `#A9640A` | 4.23 | 4.58 |
| 숫자 3 `#C07E00` | 3.07 | 3.32 |
| 숫자 4 `#3D9E52` | 3.07 | 3.33 |
| 숫자 0 `#E8467E` | 3.40 | 3.68 |

- 배경을 크림으로 바꾸는 것만으로 전 색이 한 단계 올라간다.
